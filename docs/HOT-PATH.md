## Findings and changes

The ESP source marked its render/sample functions IRAM_ATTR. The port stripped that annotation and used flash XIP for DSP. On this compiler, the inlined 12-algorithm switch and mono/poly paths produced a 47,926-byte renderBlock function. No hidden soft-double, heap or transcendental library dependency was found in the target engine object. The instruction working set and lost RAM placement are concrete port/code-generation differences; their cycle impact requires hardware measurement.

The new stepRouted evaluates each of four independent operators once in a shared path. Patch-time byte routing selects modulator inputs/carrier outputs; additions retain each original algorithm's order. The original step implementation stays as an independent graph reference in tests, but is not instantiated in target rendering. After compaction, the XIP render function was 6342 bytes; this makes RAM placement practical. The final renderer is 6866 bytes in .app_ram, with its envelope/PEG helpers and entry gateways occupying 7604 bytes total. All nine functions' closure passes upstream RAM-code checks with no allow-list exception and no call back into flash. LUT data remains in flash, which this audio-RAM contract permits; this is not a flash-off routine.

RDX_RAM_CODE and typed volatile RDX_FAR gateways follow the platform's .app_ram/long-call model. XIP callers enter renderer and gate-stage RAM code through typed far pointers; the RAM path uses direct RAM calls. Bounded reset/gain/LFO/active-state helpers are forced inline where required, including single-instruction fabs/sign wrappers. The mode is cached when applying/updating a patch instead of calling the flash singleton accessor from RAM. No function pointer is used inside the checked RAM path. Startup copying/guards/linker/update loader are upstream, unchanged.

Oscillator advance now has an exact fast wrap for nonnegative phases below two cycles, avoiding float/int conversion in the usual case. Higher increments still use the previous general wrap; signed phase-modulation lookup keeps its general wrap. Positive increment is guaranteed by valid positive frequency/detune/ratio tables. One million comparisons plus 0/1/2 boundary neighbours match the previous wrap exactly. No oscillator, envelope or LFO update rate, modulation depth, sample rate, gain, effect, pool ceiling or budget margin is reduced to obtain speed.

The importer reproducibly adds the checked RAM helpers and includes the hand-maintained class fragment rdx_voice_routing.inc. The original ESP snapshot is unchanged. A repeated import produces identical generated headers. Live algorithm changes refresh cached routing; tests cover this explicitly.

## Diagnostics

Audio Timing still opens with SEL+REC. SYN is peak synthesis time, FX is peak effect processing time, each rounded up to microseconds. 5V is the budget model's predicted total app cost at five voices; zero means no sounding-voice model yet. Its peaks/model need not refer to the same block, and SYN+FX maxima must not be added to claim a full-render maximum. APP MAX remains total app callback time; platform CPU/>90%/XRUN still cover surrounding render work. SAVE clears app/SYN/FX peaks, not the budget history. Additional timer reads/bookkeeping are bounded and included in the surrounding platform timing.

CLK 360 MHz means the platform recognizes the stock clock-register configuration; it is not a frequency-counter measurement. CLK ? means unknown (also expected in host/browser), not zero CPU speed. APP_CPU_KHZ enables readback only; clock, voltage and interrupt priorities are unchanged.

For the hardware A/B, choose the same P7, set both FX slots THRU, let transitions settle, reset timing, hold the same FOUR notes and photograph the screen. Compare APP/SYN before adding more notes; an eight-note result is a different workload. Then try eight notes, USB recording, MIDI and UI load. Retain the eight-slot ceiling and current reserves until that comparison demonstrates actual headroom; the next ceiling should follow measurements.
