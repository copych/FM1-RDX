# Adaptive polyphony — Preview 2026.11.21-12

The physical voice pool is eight, replacing four. The permitted polyphony starts at four after boot, preset/full-SysEx load, structural FX/mode changes or enabling FX. It can increase one voice every 1.5 seconds while a valid sounding poly voice provides timing observations; eight is reachable after six seconds of sufficient headroom. Silence alone never authorizes expansion. Mono retains one voice. Nonstructural live edits and FX bypass relearn costs while preserving the current limit, subject to immediate load checks, so turning a level knob does not automatically drop an eight-note chord to four.

Hold SEL and press REC: Audio Timing now shows `VOICES active/limit MAX 8`. SAVE resets timing counters only, not the budget model. Re-selecting the preset starts a fresh four-voice profile. A lower allowance is expected for heavier patches; eight is a storage ceiling, not a guaranteed hardware voice count. Previously stolen notes are not recreated when the limit grows.

## Rendering and retirement

Build a bounded list of active carrier-envelope voices once per block. Only listed slots update LFO and run synthesis. A quiet attack and a release tail remain active; amplitude/gate alone never decides whether to skip a voice. Inactive per-voice oscillators/LFO can stop because noteOn resets operators and retriggers their per-voice LFO before reuse. Disabled operators inside an active voice still advance, retaining the earlier envelope-retirement fix. Effects always run, including delay/reverb tails.

Admission uses unused slots only below the current limit; otherwise it steals the lowest existing envelope/velocity score, with the established large attack penalty and release discount, age breaking ties. A lowered limit retires the same lowest-cost nonretiring candidates, rather than arbitrary upper-numbered slots. Each retired voice fades over 32 samples (about 0.73 ms), is explicitly reset and removed from the remaining block work. This is a bounded transition, not a click-free guarantee. All-attacking pools still need a fallback candidate. Gain remains the same fixed S3-reference gain independent of physical capacity/current allowance; no automatic gain pumping or FX degradation is added.

## Budget model and limits

All decisions run on the same audio owner. The platform's 24 MHz crystal timer measures synthesis alone inside rdx_render; app_render's existing interval covers controls, complete synth+FX and output conversion. For valid steady poly blocks, per-voice cost is ceil(synthTicks/renderedVoices), and fixed cost is appTicks-synthTicks. Retain maxima for the current model. Full-occupancy prediction is fixedPeak + voicePeak * proposedLimit; per-voice averaging includes some fixed synthesis overhead, making extrapolation conservative. No ESP-specific coefficients, core affinity or startup-at-maximum scheme is reused.

Nominal block deadline is 128/44100 = 2.90249 ms. App load above 85% reduces allowance, down to one; predicted full occupancy above 85% also reduces it. Growth requires prediction below 80% (the 85% target minus a five-percent hysteresis reserve) and 1.5 seconds since the last change. The existing APP_OVERLOAD hook independently reduces a voice after a complete platform render exceeds 90%, including USB recording wrapper work and nested interrupts. App timing excludes its final bookkeeping, budget dispatch and USB tap; that surrounding work is covered by the platform warning and reserve. Costs use bounded 32-bit integer arithmetic, clamped before multiplication, and wrap-safe millisecond differences.

These thresholds are HYPOTHESIS pending FM-1 measurements. A cost observed on one note/phase is not a worst-case guarantee for every note, envelope transition or I/O combination. The guard reacts after a heavy block and cannot promise zero first-block misses. Timer interruption/jitter can conservatively lower the limit. If a single voice plus FX already exceeds the deadline, shedding voices cannot solve that workload. The controller neither shortens effects nor silently changes sample rate. It uses one core, preserving the platform model.

## First hardware run

Start with Init or a simple poly preset. Open Audio Timing, hold/play notes for 6–10 seconds, and observe the allowance. Then play eight-note chords and repeated overlapping notes for 60 seconds, including sustain/release; repeat on heavy dual-FX patches, during USB recording, and with MIDI/UI activity. Send the preset, FX state, active/limit, APP MAX, CPU, XRUN and >90% counts (a photo is fine). Check whether reductions click or cut developing notes. Compare Soundmondo loading/capture again. A single clean test is not a worst-case/soak proof; use the measurements to tune the reserve and cost model before raising the ceiling further.
